## Build & deploy (important)
`buildsite.py` reads **committed data** (CSV/JSON) → emits HTML into `site/` → CI copies to
repo root. **Vercel serves the committed ROOT html — it does NOT run buildsite.py.**

Two workflows (`.github/workflows/`):
| Workflow | Trigger | Does | Time |
|---|---|---|---|
| `publish.yml` | push to `main` (source) | rebuild from committed data, publish to root | ~1 min |
| `daily.yml` | cron `0 */3 * * *` + manual | full API scrape → commit data → rebuild | ~20 min |

- `.gitignore` excludes `config.json` (API key, built from `TP_TOKEN` secret in CI) and
  **`site/`** (regenerated build dir — do NOT re-commit it; was double-committing before
  2026-06-26 and got fixed).
- Both workflows use a **race-proof push** (on reject: `git fetch; git reset --soft
  origin/main`, retry). If your own push is rejected, `git pull --rebase origin main` then push.
- Secrets: `TP_TOKEN` (Travelpayouts fare API), `RAPIDAPI_KEY` (reprice oracle).

## Working conventions (learned the hard way)
- **Verify every changed page's `<script>` with `node --check`** — a bad escape once
  crashed a whole page's JS. Build, extract each `<script>`, check all of them.
- **Batch related edits into one commit**; avoid rapid-fire pushes (race risk).
- Keep all booking links Aviasales (marker 741311); keep the site one-way-led.
- Don't run `world.py` on the fast path (it's the ~20-min cost; cron only).
