## EPIC A — Email capture + airport segmentation  ·  priority 1 (highest ROI, small gap)
**Why:** STORM verdict = the email loop is Magellan's #1 open MAU lever. Emails are captured but with
**no airport segment**, so deal alerts can't be targeted. Closing this unlocks per-airport alerts.

**Goal:** every newsletter signup carries the subscriber's **home airport** into Beehiiv as a custom
field, so Beehiiv can segment and send per-airport deal alerts.

**Approach (respect existing wiring):**
- At signup, capture home airport: prefill from `localStorage.fs_home` if set; else offer a quick
  airport picker in the signup form (reuse the existing `city_options` / `fya-select` control).
- Pass it to Beehiiv. Beehiiv custom fields can be set via the subscribe URL query params (or the
  Beehiiv API). Update `nlSub()` (and the `data-subscribe` forms) to append the airport as a custom
  field param alongside `email`.
- Verify Beehiiv side: create the custom field (e.g. `home_airport`) + an automation/segment that
  filters by it. (Manual Beehiiv config step — document it, don't code it.)
- Keep it one-way-led and on-brand; don't break existing localStorage personalization.

**Acceptance:** a test signup with a chosen airport shows that airport on the subscriber's Beehiiv
record; a Beehiiv segment can filter by it; `node --check` passes on every changed `<script>`.

## EPIC C — AI flight/deal assistant ("first user-facing AI")  ·  priority 3 (big, the differentiator)
**Why:** Magellan's moat is its **data** (the "data + surfacing, not secrets" wedge). An assistant that
answers "where can I fly cheap from RDU in March?" from Magellan's own fare data IS the surfacing layer.

**Approach (patterns from the RV-app build — see ideas base):**
- **New serverless fn** `api/ask.js` (mirror `api/search.js` conventions: token server-side, edge cache,
  graceful degradation). It answers natural-language fare questions grounded in Magellan's committed
  data (`oneway_index.json`, `winners.json`, `oneway_pricelog.json`) and/or a live `/api/search` call.
- **Freemium cost-control (non-negotiable):** free users get **N questions/month** (e.g. 3); soft cap so
  API costs can never invert unit economics. Track by a lightweight client id / IP + edge KV counter.
- **Research-once-then-cache:** cache answers/derived data so repeated questions don't re-call the LLM.
- **Grounded, not hallucinated:** answers must cite real tracked fares and link out via **Aviasales
  (marker 741311)**; one-way-led framing; when data is thin, say so (mirror the "possible mistake fare"
  hedging discipline — never overclaim).
- UI: a simple ask box (new section or page generated by buildsite.py) → calls `/api/ask`.

**Acceptance:** ask box returns a grounded answer with real fares + Aviasales links; free-tier cap
enforced; repeated question served from cache; degrades softly (never a hard error); no hallucinated
prices.
